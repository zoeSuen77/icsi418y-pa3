# PA3 操作与提交指南

PA3 在 PA2 的注册、登录基础上增加项目管理和用户与项目的多对多关系。项目目录放在桌面 `icsi418y-pa3`；PA2 原目录可以继续保留。

## 1. 启动桌面版本

桌面项目文件夹内双击 `Start PA3.command` 即可启动并准备演示数据。也可以在终端运行：

```bash
cd ~/Desktop/icsi418y-pa3
npm ci
npm run demo
```

如果依赖已经安装，可跳过 `npm ci`。浏览器打开 **http://localhost:5173**。启动终端保持开启，按 **Ctrl+C** 停止服务。

此命令同时启动 React、Express 和真实的本地 MongoDB。第一次启动可能需要下载 MongoDB。数据库文件保存在项目里被 Git 忽略的 `.local-data` 文件夹；正常停止并重新启动后数据仍保留。本地 MongoDB 使用单节点副本集，以支持“创建项目和负责人成员关系”的事务。

应用运行后，再打开一个终端：

```bash
cd ~/Desktop/icsi418y-pa3
npm run demo:seed
```

演示数据包含：

| 用户名 | 姓名 | 演示密码 |
| --- | --- | --- |
| `alex_chen` | Alex Chen | `CampusDemo123!` |
| `maya_patel` | Maya Patel | `CampusDemo123!` |
| `sam_rivera` | Sam Rivera | `CampusDemo123!` |

两个项目为 **Campus Planner**（Planning，负责人 Alex）和 **Study Together**（Active，负责人 Maya）。脚本只补充不存在的演示用户和项目，不重置已有账户密码或成员关系。如果已有同名账户，应使用原密码。重新录制前，在界面中移除这两个项目里的 Sam，便于再次展示添加流程。

## 2. 试用与检查

1. 用一个新用户名注册，确认成功，再登录该账号。
2. 创建项目，填写名称、描述，选择状态和数据库中的负责人。
3. 查看项目列表：应显示名称、描述、状态和负责人的姓名或用户名。
4. 打开新项目成员列表，确认负责人已经自动加入。
5. 选择 Sam 添加为成员，确认列表刷新。
6. 再添加同一个 Sam，确认出现重复成员错误。
7. 切换另一个项目，把 Sam 也加入，展示同一用户可以属于多个项目。
8. 返回第一个项目，删除 Sam，确认第二个项目的 Sam 仍在。
9. 负责人应该一直保留在成员列表中；后端也会拒绝删除负责人。

如果注册了新用户后下拉列表尚未显示，可点击项目页的 Refresh。状态必须是 `Planning`、`Active` 或 `Completed`。必填字段、用户和项目 ID、重复成员等检查同时在后端执行。

## 3. 查看实际 MongoDB 数据

服务运行时，在第二个终端执行：

```bash
npm run db:inspect -- --local
```

也可以打开 MongoDB Compass，连接：

```text
mongodb://127.0.0.1:27018/?directConnection=true
```

选择 `pa3` 数据库，检查：

| 集合 | 演示重点 |
| --- | --- |
| `Users` | 注册用户的 `_id`、姓名和用户名；密码为哈希 |
| `Projects` | 名称、描述、状态，以及 `project_lead_id` |
| `ProjectMemberships` | `project_id` 和 `user_id` 组成一条成员关系 |

`project_lead_id`、`project_id`、`user_id` 在数据库里均为 **ObjectId**。找到 Sam 的 `_id`，再展示两个项目中该 `user_id` 的成员文档，能直观说明多对多关系。HTTP 返回的 ID 字符串只是 JSON 表示，不代表数据库存的是普通字符串。

## 4. 使用 Atlas 和 PA2 原有用户

先停止 `npm run demo`。复制 `server/.env.example` 为 `server/.env`，设置自己的 MongoDB Atlas 连接串和网络访问权限，再执行：

```bash
npm run dev
```

`npm run demo` 固定使用本地数据库；`npm run dev` 使用 `.env` 的数据库配置。两种模式不要同时运行。

新 PA3 数据库推荐：

```dotenv
DB_NAME=pa3
USERS_COLLECTION=Users
```

如果要使用 PA2 已有的 Atlas 用户，在相同 Atlas 连接串下设置：

```dotenv
DB_NAME=pa2
USERS_COLLECTION=users
```

这样可以直接复用原用户、ObjectId 和密码哈希，项目及成员关系保存在 `pa2` 数据库的新集合中。MongoDB 集合名区分大小写；新建 PA3 默认使用作业中的 `Users`、`Projects`、`ProjectMemberships`。如果老师要求名称严格一致，使用新 PA3 数据库并准备演示账号即可。

项目创建使用事务，所以自行配置的 MongoDB 也要支持事务：Atlas 或启用副本集的本地 MongoDB 均可。项目自带的 demo 模式已配置副本集。

## 6. 测试和理解代码

```bash
npm test
npm run build
```

浏览器测试使用独立端口 5174、9001、27019 和 `pa3_ui_test` 数据库，可以与演示同时运行：

```bash
PLAYWRIGHT_CHANNEL=chrome npm run test:ui
```

未安装 Chrome 时，可用 `npx playwright install chromium` 安装测试浏览器，再运行 `npm run test:ui`。实际执行结果见 [VERIFICATION.md](VERIFICATION.md)。

理解以下流程就能解释主体代码：

- React 保存表单、项目选择、成员列表与反馈状态；共享 API 辅助函数通过 `fetch` 发请求。
- Express 验证字段、状态和 ID，并检查相关用户/项目是否存在。
- 创建项目时，事务同时写入项目文档和负责人对应的成员关系。
- 成员表的 `(project_id, user_id)` 唯一索引阻止重复加入，也能处理同时发生的请求。
- 删除成员前查询负责人 ID，确保负责人不能被删除。
- 接口只返回用户公开信息；密码沿用 PA2 的 `scrypt` 哈希处理。

本项目保留 PA2 的登录成功提示。点击 Projects 或登录成功后的项目入口即可管理项目；本作业未增加持久登录会话或 API 权限控制。

## 7. 新 GitHub 仓库与提交

PA3 使用独立的 `icsi418y-pa3` 仓库，PA2 仓库继续保留。新仓库是否已创建、推送，以交付消息和实际 GitHub 页面为准。

如果还需要手动上传：在 GitHub 账号中创建空仓库 `icsi418y-pa3`，不要初始化 README。打开桌面的 PA3 目录，先检查远程地址：

```bash
git remote -v
```

如果 `origin` 仍指向 PA2，先改为 PA3；如果还没有 `origin`，使用 `git remote add origin` 替代下面的 `set-url`：

```bash
git remote set-url origin https://github.com/zoeSuen77/icsi418y-pa3.git
git status
git add .
git commit -m "Complete PA3 project and membership management"
git push -u origin HEAD:main
```

如果所有内容已经提交，跳过 `git add` 和 `git commit`。推送完成后，在 GitHub 检查 README、前后端代码和文档是否为 PA3 最新版本；老师需要有访问权限。不要把整个课程目录上传。
